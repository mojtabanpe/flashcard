# Recall MCP for ChatGPT

Sign in to Recall and select **ChatGPT** in the header, or open `/api/mcp/setup`.
Create a personal token and copy it: the raw token is displayed only once.

In ChatGPT, add a custom MCP server:

- Server URL: `https://poshtetgarm.ir/api/mcp`
- Authentication: OAuth
- Client ID / secret: leave empty (dynamic client registration)

On the Recall authorization page, paste the personal token and select **Authorize connection**.
Install/select the resulting connection in a conversation. For example:

> Create a B1 passage about travel, save it, and add 10 vocabulary cards to my English deck.

ChatGPT generates the content; MCP saves it through the existing owner-scoped services.
No OpenAI API key is needed by this server.

## Tools

| Tool | Permission | Inputs |
| --- | --- | --- |
| `list_decks` | `cards:read` | none |
| `get_deck` | `cards:read` | `deck_id` |
| `create_deck` | `cards:write` | `name`, optional `description`, `color` (default `sky`) |
| `update_deck` | `cards:write` | `deck_id`, at least one of `name`, `description`, `color` |
| `delete_deck` | `cards:write` | `deck_id`; permanently deletes all cards in the deck too |
| `get_card` | `cards:read` | `card_id` |
| `search_cards` | `cards:read` | `query`, optional `deck_id`, `limit` (1–100, default 50), `offset` |
| `delete_card` | `cards:write` | `card_id`; permanent |
| `move_card` | `cards:write` | `card_id`, destination `deck_id` |
| `review_card` | `cards:write` | `card_id`, `rating`: `again`, `hard`, `good`, `easy` |
| `suspend_card` | `cards:write` | `card_id` |
| `unsuspend_card` | `cards:write` | `card_id`; resets lapses to zero |
| `list_cards` | `cards:read` | `deck_id`, optional `due_only` |
| `create_card` | `cards:write` | `deck_id`, `front`, `back`, optional `unit`, `examples` |
| `update_card` | `cards:write` | `card_id`, at least one of `front`, `back`, `unit`, `examples` |
| `list_readings` | `readings:read` | none |
| `get_reading` | `readings:read` | `id` |
| `create_reading` | `readings:write` | `title`, `body` |
| `update_reading` | `readings:write` | `id`, at least one of `title`, `body` |
| `delete_reading` | `readings:write` | `id`; permanent |

Creation tools are non-idempotent: retrying a completed call creates another item.
Use `list_cards` to find an existing card's ID, then `update_card` to replace only
the supplied content fields. Omitted fields remain unchanged. `front` and `back`
must stay nonempty; use `""` to clear `unit` or `examples`. Updates preserve the
card ID, deck, creation date, review counts, ease, suspension state and schedule.
For example, to remove a Persian translation from an answer, send the same
`card_id` with the remaining answer in `back`; do not recreate the card.
`search_cards` matches a case-insensitive literal substring across front, back,
examples and unit, scoped to the token owner. Page results with `limit` and `offset`.
`move_card` preserves content and review state and requires ownership of both card
and destination deck. Manual suspension hides a card without increasing its leech
suspension count; unsuspension uses the app's existing behavior (clears lapses).
`review_card` uses the existing scheduler and can suspend leeches. Only submit
ratings supplied by the user; repeating a successful review advances it again.
Deletes are permanent. Deleting a deck also deletes all of its cards and review
state. Mutation tools advertise destructive/idempotent hints as appropriate.
Existing scope names are unchanged; new tools use the same owner-scoped permissions.
After deployment, clients may need to refresh their cached tool list.

## Tokens and authentication

Personal tokens expire in 90 days. Revoke them on `/api/mcp/setup`; revocation
immediately disables linked OAuth access/refresh tokens. They can also be used
directly as `Authorization: Bearer recall_mcp_…` by MCP clients supporting static
bearer authentication. Browser sessions cannot authenticate protocol requests.

Session-authenticated management endpoints retain the existing web CSRF checks:

- `GET /api/mcp/tokens`: list your token metadata (never raw tokens/hashes).
- `POST /api/mcp/tokens`: `{ "name": "ChatGPT", "scopes": ["cards:read", "cards:write"] }`.
  `scopes` is optional and defaults to all four permissions.
- `DELETE /api/mcp/tokens/:id`: revoke an owned token and its linked grants.

Personal, access, refresh and authorization-code secrets are stored as SHA-256
hashes. OAuth clients and grants persist in Postgres across process restarts.
OAuth authorization uses S256 PKCE, registered callback matching, browser-bound
consent, one-use codes (5 minutes), access tokens (1 hour), and rotating refresh
tokens (30 days). Account bans/deletion and personal token expiry are checked
on each authenticated request. Client secrets generated by the MCP SDK for
confidential OAuth clients are retained in the private client metadata table;
public clients use `token_endpoint_auth_method=none` with PKCE.

## Configuration and deployment

`MCP_PUBLIC_URL` is the public HTTPS origin, such as `https://poshtetgarm.ir`.
It defaults to the first `APP_ORIGINS` entry. Do not derive it from a request's Host header.
Local HTTP origins are accepted only outside production.

`MCP_REDIRECT_HOSTS` optionally lists exact HTTPS callback hosts, defaulting to
`chatgpt.com,chat.openai.com`. The authorization server advertises DCR, not CIMD.
Use dynamic registration when adding the connection in ChatGPT. Local loopback
HTTP callbacks are accepted only outside production.

The reverse proxy must route these paths to the API without rewriting them:

- `/api/mcp` and its `/setup`, `/tokens`, `/consent` subpaths
- `/authorize`, `/token`, `/register`, `/revoke`
- `/.well-known/oauth-authorization-server`
- `/.well-known/oauth-protected-resource/api/mcp`

The existing Nginx catch-all proxy already handles these paths. MCP is stateless
Streamable HTTP with JSON responses; a persistent SSE connection is not required.
The normal web CSRF middleware remains in effect outside the exact protocol and
OAuth routes. SDK endpoints and MCP/consent endpoints have request rate limits.

Run `pnpm api:test` with `DATABASE_TEST_URL` pointed at a disposable Postgres
database. The MCP integration suite covers discovery, PKCE, consent CSRF, scope
checks, cross-account ownership, restart persistence, refresh rotation, bans and
revocation. It does not connect to a real ChatGPT account.

### Building on a small production host

Prefer building the normal `Dockerfile` in CI and transferring its image. If a
host build is necessary, compile locally with `pnpm build && pnpm api:build`,
then transfer the sources plus `dist/flashcard/browser` and `server/dist`.
Build with `docker build -f deploy/Dockerfile.prebuilt -t flashcard:RELEASE .`.
Its Dockerfile-specific ignore file includes these compiled artifacts while
excluding secrets and dependency folders. It reuses the normal dependency
layers and keeps the same non-root runtime and health check, without running
Angular or TypeScript compilation on the production host.
